# ADR-001: Split the work across three agents (planner, builder, reviewer)

## Status
Accepted

## Context
The workflow has six fixed stages: requirements, design, implementation,
testing, release, review. We must decide how many agents carry them out
(decision D1). Three options were considered:

1. **One agent for everything.** Simplest to build. But one long conversation
   accumulates the spec, the design, failed attempts and test logs. Small and
   free models lose track in long contexts. The same agent would also review
   its own work, which defeats the independent-reviewer requirement.
2. **One agent per stage (six agents).** Each agent has a tiny, focused
   prompt. But every hand-off is a place where information is lost, each
   adds a model call and a possible failure, and free-tier rate limits make
   the extra calls expensive. Stages 3 and 4 are tightly coupled: failing
   tests need the builder's context to be fixed.
3. **Three agents grouped by role.** Planner (stages 1-2), Builder (stages
   3-4), Reviewer (stage 6). Release (stage 5) is plain code, not an agent,
   because it only runs `git push` and `gh pr create` and needs no judgment.

Constraints: free-tier models only (see ADR-006), a public fork, and a
requirement that the reviewer must not see the implementer's reasoning.

## Decision
Use three agents:

| Agent | Stages | Why grouped |
| --- | --- | --- |
| Planner | 1 Requirements, 2 Design | Both are reading and writing documents; design needs the spec fresh in mind. Neither edits code. |
| Builder | 3 Implementation, 4 Testing | Fixing failing tests needs the context of the code just written, so the build-test loop stays inside one agent. |
| Reviewer | 6 Review | Must be independent: separate job, separate prompt, separate model, read-only. |

Stage 5 (Release) is deterministic workflow code, not an agent.

## Consequences
- Each agent keeps a short, focused context, which suits weaker models.
- Only two hand-offs between agents (Planner to Builder through `spec.md` and
  `design.md`; Builder to Reviewer through the pull request), so less
  information is lost than with six agents.
- The Builder carries two jobs, so a bad design is discovered late, at the
  test stage; the workflow therefore lets the Builder escalate back to the
  Planner (see ADR-002).
- The Planner's output is not independently checked by another model, only by
  deterministic checks (see ADR-007). A bad spec could pass if it merely looks
  testable.
- This split is testable. A candidate experiment is comparing it against a
  single-agent variant on the same issues (see `experiment/variants.md`).
- Related: ADR-002 (control flow), ADR-003 (hand-offs), ADR-008 (reviewer
  independence).
