# ADR-003: Hand-offs pass files and the repository, never conversations

## Status
Accepted

## Context
Agents need information from earlier stages (decision D3). We must decide what
each agent receives and what is deliberately left out. Options considered:

1. **Pass the full conversation** of the previous agent. Maximum information,
   but it is long (a problem for small context windows on free models), it
   carries the previous agent's mistakes and assumptions forward, and it would
   destroy the Reviewer's independence.
2. **Pass summaries written by the previous agent.** Short, but a summary is
   the author's own opinion of its work and can hide problems or drop details.
3. **Pass the finished artifacts and give read access to the repository.**
   Each agent receives the documents the previous stage produced and can look
   at the code itself.

## Decision
Use option 3: hand-offs are the stage artifacts plus the repository, and
nothing else.

| Receiver | Receives | Deliberately NOT given |
| --- | --- | --- |
| Planner | Issue title and body (as untrusted data), `SKILL.md`, `ARCHITECTURE.md`, read access to the repo | Anything from earlier runs |
| Builder | `spec.md`, `design.md`, the repo checked out on a new branch, and (on a retry) the failing test output | The issue text, Planner's reasoning |
| Reviewer | The issue text, the diff, and the repository at the PR head commit | `spec.md`, `design.md`, `test_report.md`, the Builder's or Planner's conversations and reasoning, PR description written by the Builder |

Rules:
- Artifacts are plain files (`spec.md`, `design.md`, `diff.patch`,
  `test_report.md`, `pr.md`, `review.md`), so a human can read exactly what the
  next agent saw.
- Issue and comment text is always wrapped and labelled as untrusted data
  (see ADR-009).
- On a retry, the Builder gets only the failing test output and the previous
  diff, not the whole earlier attempt.

## Consequences
- Contexts stay small, which suits free models with limited input size.
- Because the Reviewer gets no spec or design, it judges the change against
  the issue only. It may flag something the spec intentionally excluded.
  This is accepted: independence matters more than agreement.
- The Builder does not see the original issue, only the spec. If the Planner
  mis-states the issue, the Builder will faithfully build the wrong thing. The
  Reviewer, who sees the issue, is the safety net for this.
- Hand-offs are inspectable after the fact, which satisfies the requirement
  that anyone can follow a run through its artifacts.
- Related: ADR-001 (agent split), ADR-004 (state), ADR-008 (reviewer
  independence), ADR-009 (prompt injection).
