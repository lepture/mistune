# ADR-004: State lives in workflow artifacts and a run log, not on the branch

## Status
Accepted

## Context
Information must survive between stages (each in its own job on a fresh
runner), and between runs (restarts, re-runs, later review), decision D4.
Options considered:

1. **Files committed on the working branch** (`spec.md`, `design.md`, ...).
   Persistent and visible, but they pollute the pull request diff, which the
   Reviewer must judge, and they are mixed with the code under review.
2. **Pull request comments.** Visible to humans, but they are free text, can
   be edited by anyone with access, and the PR does not exist until stage 5.
3. **Workflow artifacts** (`actions/upload-artifact`). Each stage uploads its
   output; the next job downloads it. Not part of the code, tied to the run.
4. **Actions cache.** Fast, but can be evicted and is not meant as a record.

## Decision
- Each stage uploads its artifact (`spec.md`, `design.md`, `diff.patch`,
  `test_report.md`, `pr.md`, `review.md`) as a **workflow artifact**. This is
  the source of truth between jobs and the record humans inspect.
- A small `run_state.json` artifact records the current stage, retry counts,
  review round, branch name and the outcome of every check. The state machine
  (ADR-002) reads and updates it.
- The **pull request** receives a short status comment (written by workflow
  code, not by an agent) with links to the run and artifacts, so a maintainer
  can follow the run from the PR.
- Nothing but the code change is committed to the branch; artifacts never
  enter the diff.
- The branch is named `autose/issue-<number>-<run_id>`, so a restart never
  overwrites an earlier attempt.
- Restarts: stages are written to be idempotent. Re-running failed jobs
  re-downloads earlier artifacts and continues from the failed stage. A fresh
  trigger starts a new run with a new branch and does not reuse older state.

## Consequences
- The PR diff contains only code, which keeps the review focused.
- Artifacts expire (GitHub default retention), so the permanent record for the
  report is the links in `results/runs.md` plus copies of key artifacts saved
  into the repo when experiments finish.
- Passing state through artifacts adds upload and download steps and time to
  each job.
- Old runs leave stray branches and possibly PRs; closing them is manual.
- Related: ADR-002 (control flow), ADR-003 (hand-offs).
