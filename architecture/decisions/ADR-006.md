# ADR-006: Free-tier models from three families; the reviewer is different from planner and builder

## Status
Accepted

## Context
We must choose a model for each role (decision D6), weighing ability, cost,
speed and the value of using different models. Constraint: no paid API access;
only free tiers. Observed limits (read from the providers' consoles on
2026-11-21; they may change, and this ADR is superseded if a model proves
unavailable or unusable):

| Provider / model | Req/min | Req/day | Tokens/min | Tokens/day |
| --- | --- | --- | --- | --- |
| Gemini 2.5 Flash Lite | 10 | 20 | 250K | n/a |
| Gemini 3 Flash / 2.5 Flash | 5 | 20 | 250K | n/a |
| Groq `openai/gpt-oss-120b` | 30 | 1K | 8K | 200K |
| Groq `openai/gpt-oss-20b` | 30 | 1K | 8K | 200K |
| Groq `qwen/qwen3.8-27b` | 30 | 1K | 8K | 200K |

Gemini gives a large context but only 20 requests per day per model. Groq
gives many requests but only 8K tokens per minute, so each prompt plus reply
must be small. Options considered:

1. **One model for every role.** Simplest, but no independence for the
   reviewer, and one daily quota would be exhausted quickly.
2. **Two families (for example Gemini and one Groq model).** Independent
   reviewer, but the reviewer shares a family with either the planner or the
   builder.
3. **Three families, one per role.**

## Decision
Option 3.

| Role | Model | Reason |
| --- | --- | --- |
| Planner | Gemini, Flash-class (2.5 Flash Lite as default) | Few calls needed; large context fits the issue, `SKILL.md` and `ARCHITECTURE.md`; the 20 requests per day are enough for a handful of runs |
| Builder | Groq `openai/gpt-oss-120b` | Strongest coding model among the free options; most calls happen here, so it needs the 1K requests per day |
| Reviewer | Groq `qwen/qwen3.8-27b` | A different family from the planner (Google) and the builder (OpenAI), so the reviewer shares no training lineage with either (ADR-008); separate quota |

Model names are read from repository variables (`PLANNER_MODEL`,
`BUILDER_MODEL`, `REVIEWER_MODEL`), so they can be changed without editing code
and are recorded per run in `results/runs.md`. Keys are repository secrets
(`GEMINI_API_KEY`, `GROQ_API_KEY`).

## Consequences
- Zero money cost, so the spending limit is trivially met. Token usage is still
  logged per call and reported in total.
- Small-context models force range-limited tools and short prompts (ADR-005),
  and pacing to stay under 8K tokens per minute (ADR-009).
- The Gemini quota (20 requests per day) caps how many runs the planner can
  serve per day, so experiments are spread over several days.
- Free models are weaker at editing code, so we expect more failed runs and
  more retries; failures are reported honestly.
- The reviewer model is the smallest of the three, so it may be a weaker judge.
  This is the price of three independent families and is measured with the
  seeded pull requests (ADR-008).
- Tool calling support and code quality of these models on the free tiers are
  not verified; the first real runs decide whether this ADR needs to be
  superseded.
- Free-tier prompts may be used by providers to improve products. The fork is
  public and no secrets go into prompts.
- Related: ADR-001, ADR-005, ADR-008, ADR-009.
