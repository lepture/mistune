# ADR-007: Stage checks are deterministic code; models never decide pass or fail

## Status
Accepted

## Context
Each stage has a required check before moving on (decision D7). We must decide
how checks are carried out (tests, static analysis, an LLM judge, or a mix) and
who makes the final pass/fail decision. An LLM judge is flexible but can be
persuaded by fluent text, varies between calls, and costs extra calls on a
limited free quota. Programmatic checks are repeatable but can only check what
we can express in code.

## Decision
Checks are deterministic scripts run by the state machine (ADR-002). The
workflow code, not a model, makes the final pass/fail decision.

| # | Stage | Check (in code) |
| --- | --- | --- |
| 1 | Requirements | `spec.md` parses; has an Acceptance criteria section with at least one `ACn:` line; every AC contains a concrete example (an input and an expected result); vague words (for example "properly", "correctly", "better", "fast") are rejected; `BLOCKED:` marker stops the run |
| 2 | Design | `design.md` lists files that exist in the repo and functions that can be found in those files by search; at least one file is named; every AC is referenced by the plan |
| 3 | Implementation | Package installs and imports; the diff is non-empty and only touches allowed paths; linting/type check does not get worse |
| 4 | Testing | Each AC has at least one new test (tests are named or tagged `ACn`); the full test suite passes; the new tests fail without the code change and pass with it |
| 5 | Release | Branch pushed, PR open, CI status on the PR head is success |
| 6 | Review | `review.md` has a valid structured verdict; `approve` is accepted only if evidence is present and CI is green |

The one place a model gives an opinion is stage 6, and its verdict is still
validated and can be overridden by code (ADR-008).

## Consequences
- Checks are repeatable, cheap (no extra model calls) and explainable.
- A spec or design can pass the checks and still be wrong: the checks verify
  form (testable, files exist), not meaning. The reviewer, who sees the
  original issue, is the only semantic check on the spec and design.
- The "new tests fail without the change" check in stage 4 costs extra test
  runs but guards against tests that prove nothing.
- Writing the checks is real work, and they need their own unit tests.
- Related: ADR-002 (control flow), ADR-008 (reviewer independence).
